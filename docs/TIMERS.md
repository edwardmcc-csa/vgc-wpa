Week 4, Task 7. This is a **decision document**: nothing in the state schema

## 1. Summary

- **The table is right.** Replaying 84,738 Reg M-A and 4,167 Reg M-B games, 98%
  of the effects that started and later ended ended on exactly the predicted
  turn. A further 2% ended early with a cause the log names (Defog, Brick
  Break, Screen Cleaner, Mental Herb, using Trick Room again). Only **62 of
  89,099 (0.07%) in Reg M-A and 5 of 4,763 (0.10%) in Reg M-B** ended on a
  different turn with no cause. Another 121,000 effects never ended in the log
  (game over, Pokemon switched or fainted, weather replaced) and are counted as
  *censored*, not as matches.
- **Almost every length is knowable.** Of 103 timed effects, 101 are class (a):
  fixed once you know the start turn, the phase it started in, and the items
  and abilities on the open team sheet. Two are class (b), random with a known
  distribution: `partiallytrapped` (5 or 6 turns) and `lockedmove` (2 or 3).
  Sleep, freeze and confusion are class (b) countdowns that depend on an
  observable attempt count. **Class (c), truly hidden, is empty.**
- **The replay path can have timers today without a re-parse.** Everything
  needed is in the raw logs. The live path cannot get them from poke-env
  as it stands (section 6).
- **Decision for the PO (section 7):** add a `Timer` record to `BattleState`
  (costs a ~103 minute re-parse) or keep timers in a side file keyed by game and
  turn (no re-parse, no schema change). My recommendation is the side file now,
  the schema field only when a model needs it.

## 2. How the length rule works

A move used in turn T (T 1 or later) puts an effect in force for turns T to
T+D-1 and removes it in the residual of turn T+D-1. An effect set after the
turn's residual (a replacement switch-in) or at turn 0 (leads) is removed in the
residual of turn T+D. A decision at turn N therefore sees
`max(0, scheduled_end - N + 1)` turns left, counting the current one.

Lengths that change: Light Clay (screens 8), Terrain Extender (terrain 8), the
weather rocks (8), Persistent (the rooms, Safeguard, Gravity, Tailwind 6), Grip
Claw (trap 8). Three effects shift by one turn depending on move order: Encore
and Taunt +1, Disable -1. All come with a source line in `docs/DURATIONS.md`.

## 3. The leakage rule

Turns remaining are computed from the **start turn and the table only**, never
from the end event. `turns_remaining` has no end-event parameter (a test checks
the signature), and `GameTimers.snapshots` is built at each `|turn|N` line from
what has been seen so far. Two tests prove it: the snapshot at turn N is
identical whether the log is cut at turn N or run to the end, and moving or
deleting the later end event changes nothing before it.

- **Encore, Taunt, Disable:** class (a) but the one-turn ordering adjustment
  depends on who moves first that turn. In Reg M-A, 92% of Encores matched and
  6% ended early with a named cause (Mental Herb); every Taunt and Disable
  matched or had a named cause. The remaining 2.0% (Reg M-A) and 3.2% (Reg M-B)
  of Encores ended *one turn earlier* than predicted. In the examples I read,
  the target had used Protect or a move that failed. This is a small
  imperfection in my ordering test, not yet fixed.
- **Wish, Future Sight / Doom Desire:** class (a) turn-stamped (Wish 2,
  Future Sight 3). Wish: 149 of 154 matched; the 5 misses are the log not
  printing a heal when the target is at full HP, so the logged "end" is a later
  event. Future Sight: 35 of 36; the miss is a Future Sight that failed.
- **Items and abilities that remove an effect:** Mental Herb (ends Encore, Taunt,
  Disable, Heal Block), Screen Cleaner, Defog, Brick Break, Psychic Fangs,
  Raging Bull, Steel Roller. These are *events*, not lengths. Because the team
  sheets are open the observer knows who holds them, but whether they fire is up
  to the opponent, so they are a feature ("can be cut short"), not a timer.
- **Sleep, freeze, confusion:** counts of prevented attempts are observable, so
  the chance of ending next attempt is a function of that count. Checked on the
  logs, counting the countdowns that were cut off (without that the check is
  biased towards short sleeps):

  | Effect | Attempt | Expected | Observed |
  |---|---|---|---|
  | Sleep (M-A) | 2 | 33.3% | 33.0% |
  | Sleep (M-A) | 3 | 100% | 100% |
  | Freeze (M-A) | 1 / 2 | 25% / 25% | 27.1% / 24.3% |
  | Confusion (M-A) | 2 / 3 / 4 | 25% / 33% / 50% | 25.9% / 35.9% / 52.4% |

  Left open: sleep ending at attempt 1 (table says never) in 0.8% of at-risk

  item or ability that the walker read as a natural end. Not chased; the
  estimates for later attempts agree with the table.
- **Paralysis (1/8), Attract (1/2), Protect chains (1/counter):** chances per

## 5. Proposed `Timer` record

One record for the live and replay paths. Field names follow the code that
already exists in `wpa/timers.py`.

```python
@dataclass(frozen=True)
class Timer:
    kind: str                    # side | field | weather | volatile | slot
    id: str                      # showdown id, e.g. "tailwind", "encore"
    side: str                    # "p1", "p2", or "field"
    target: str | None           # the affected Pokemon, for volatiles
    name: str                    # display name
    start_turn: int
    start_phase: str             # "action" or "after_residual"
    durations: tuple[int, ...]   # possible lengths; one value when class (a)
    extended_by: tuple[str, ...] # e.g. ("item: lightclay",), ("move: ...",)
    # not stored; derived at a decision point N from the fields above:
    #   turns_remaining(N) -> per length, max(0, scheduled_end - N + 1)
```

`BattleState` would get `timers: tuple[Timer, ...]` (default empty, so older
files still load) plus, for sleep / freeze / confusion, the observable count
(`attempts_prevented`) on the status record. Nothing about the end is stored:
that is the leakage rule.

## 6. What poke-env exposes on the live path

Checked at the pinned commit `379a046` of the `vgc-bench` fork.

| Need | Live path (poke-env) | Verdict |
|---|---|---|
| Side conditions (Tailwind, screens) | `battle.side_conditions`: `{condition: start turn}` (a count for stackables) | Start turn present. No phase. |
| Fields and terrains (Trick Room, terrains) | `battle.fields`: `{field: start turn}` | Start turn present. No phase. |
| Weather | `battle.weather`: `{weather: turn}` | **Wrong.** The handler rewrites the turn on every `|-weather|...|[upkeep]` line, so it holds the *current* turn, not the start. |
| Volatiles (Encore, Taunt, Disable, Heal Block) | `pokemon.effects`: a counter of turns active, no start turn | Start can only be inferred as now minus counter; no phase. |
| Status counters | `pokemon.status_counter` (toxic stage, sleep attempts) | Present. |
| Slot conditions (Wish, Future Sight) | not tracked | Missing. |
| Items and abilities of the opponent | open team sheet only if our parser reads `|showteam|` | Not in poke-env. |

Our own replay parser (`wpa/observations.py`) records only the *names* of side
conditions, fields and weather today, with no turns, so the replay path also
has nothing to build timers from without reading the log again.

Patching poke-env is an upstream change and is out of scope for me. The
alternative that needs no patch: run the same walker that validated the table
over the live message stream, incrementally. That gives one implementation for
replay and live, which is what the one-schema requirement asks for. It needs a
small `feed(line)` interface added to `wpa/timers.py` (the walker is currently
whole-log).

## 7. Decision for the PO

**Decided 27 Oct 2026: option A.** Timers live in a side file keyed by game
and turn. No schema change and no re-parse. The Week 5 model reads that file.

| Option | Schema | Re-parse | Live path | Notes |
|---|---|---|---|---|
| A. Side file (recommended now) | none | none | via the incremental walker | `GameTimers.snapshots` already gives per-turn timers for every game; written as a file keyed by game tag and turn. |
| B. `timers` on `BattleState` | one additive field | **~103 min** (all games) | via the incremental walker | Do this when a model consumes timers during training, so the cost is paid once. |

## 8. Known gaps

- Encore ordering misses (2.0% / 3.2% of Encores, one turn early).
- Sleep and confusion ending at attempt 1 in under 4% of at-risk cases.
- Future Sight and Wish rows are tiny samples (36 and 154 in Reg M-A).
- Weather replacement is censored: when new weather overwrites old, the old
  weather's end is not judged.
- Reg M-B has about 5% of the data of Reg M-A; its rates carry more noise.
- The incremental live walker does not exist yet (section 6).

## 9. Built after the decision (27 Oct 2026)

- **Side file:** `python -m wpa.timers --timers-out timers.jsonl.gz` writes one
  line per game with, for each turn, the effects in force (fewest and most
  turns left; they differ only for random lengths) and the attempts a sleep,
  freeze or confusion has prevented so far. Read it with
  `wpa.timers.read_timer_file`. It holds no end turn and no end reason. Run on
  the full corpus: 88,905 games, 79,962 with at least one timer. Since Week 5
  Task 3 it also holds the timers at every stored decision point (6.5 MB; see
  `docs/TIMER-JOIN.md`).
- **Live tracker:** `wpa.timers.TimerTracker` takes the battle one protocol line
  at a time. Replay is now just the same tracker fed every line, so the two
  paths cannot disagree; rerunning a shard of 11,000 real games gave identical
  counts to before the change. It is not yet wired into the live bot, and
  poke-env's own weather start turn is still wrong. The bot has to feed
  `TimerTracker` the raw messages itself.
